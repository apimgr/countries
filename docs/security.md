# Security and privacy

## Service model

Country data reads are public and read-only. There are no user accounts. Owner-token management and report submission are separate server operations; MCP requires a bearer token. Request inputs and bodies are bounded and validated. The service embeds country data and does not call external services for lookups.

Optional analytics can be configured with `server.tracking`. Provider scripts are rendered only after analytics consent; they are absent for requests served through onion and I2P addresses. The same-origin `/server/tracking.js` endpoint returns 404 if tracking is disabled, consent is absent, or the request uses an overlay address. See [configuration](configuration.md#analytics-tracking) for provider options and privacy behavior.

Every response receives a request ID. Rate limiting is always on and its request/window values are configurable. Anonymous traffic is keyed by client IP, valid bearer-token traffic by token, and failed authentication by IP. The server honors client-address headers only from a trusted immediate proxy and sends configured security headers, including Content-Security-Policy. By default, rate-limit counters are stored in `server.db`; a configured Valkey or Redis cache stores the sliding windows instead. If that cache becomes unavailable, the limiter warns once, marks cache health degraded, and falls back to in-memory counters seeded from persisted database counters.

The server honors `Sec-GPC: 1` by suppressing analytics and preference-based personalization, records a compliance audit event, and shows a notice on the preferences page. `DNT: 1` has the same behavior only when `web.headers.honor_dnt` is enabled. Frontend state-changing requests reject a present `Sec-Fetch-Site: cross-site` signal unless a Bearer token or configured CSRF exemption applies; missing Fetch Metadata headers remain compatible with older browsers. API and compatibility routes are outside that check.

Linked-token revocation and withdrawal of a previously granted non-essential consent send `Clear-Site-Data: "cache", "storage"` by default. Configure `web.headers.clear_site_data` to control those events; `execution_contexts` is off by default because it reloads browser tabs.

Access logs include request ID, method, path, status, and duration. Sensitive query parameter values and referer values are redacted in every access format; JSON access logs omit the query string. Successful health probes are suppressed from access logs and console request lines, while failed probes remain logged. Do not put secrets or sensitive personal data into URLs or request IDs.

## Health and reporting

`/server/healthz` is a public frontend route with normal content negotiation: browsers receive HTML, explicit `Accept: application/json` receives the bare health object, and text clients receive its text form. `/api/v1/server/healthz` returns the same bare JSON object by default; the `.txt` suffix selects its text form. The optional `/healthz` path maps directly to the same handler when `server.healthz.root.enabled` is true. Health output includes version and build information, enabled features, component checks, the public-safe database engine/locality labels, and `requests_total`, `requests_24h`, and `active_connections` statistics. It does not expose credentials, filesystem paths, or internal addresses. Health endpoints are public, including while the service is in maintenance mode.

The service publishes canonical `/.well-known/security.txt` with GitHub private reporting, the deployment report form when enabled, a configured security email when present, policy, and annual expiration fields; `/security.txt` is not served. `/llms.txt` and `/.well-known/llms.txt` provide API discovery. The human-readable overview is `/server/security`, the disclosure policy is `/server/security/policy`, and researcher acknowledgments are listed at `/server/security/thanks`. Unknown `/.well-known/*` entries return 404. When a security-report PGP public key exists, `/.well-known/pgp-key.asc` serves it as `application/pgp-keys`; otherwise that endpoint returns 404. The overview links to the machine-readable security.txt, policy, acknowledgments, and key when available. The CSP/Reporting API receiver is `/api/v1/server/reports/{report}` and accepts supported report media types with a 1 MiB body limit; public reports are limited per IP by the configured per-minute and short-burst limits.

## Report a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/apimgr/countries/security/advisories/new) for vulnerabilities in the project. Do not file vulnerability details in public issues. For a self-managed deployment, use the reporting link on `/server/security`; it issues a rotating security identifier and stores report bodies encrypted at rest. The emailed `/server/security/report/{tracking_id}?token={status_token}` page exposes only the triage state, researcher-visible comments, and expected disclosure date. Its status token can be used once per UTC day and expires 30 days after closure. When `security/pgp.pub.asc` in the configured configuration directory is present and valid, the body and maintainer notification use that OpenPGP key. Without a key, the body and notification attachment use AES-256-GCM with `server.security.encryption_key`. Researcher contact details always use AES-256-GCM because the server needs to read them for status notices. The report form requires a confirmation step before ordinary reports are delivered. It handles abuse and terms violations at URLs on the site, DMCA notices, and privacy requests only. It does not accept support, bug reports, feature requests, or general questions.

## GPG keypair management

Manage the project security key on the machine running the server with `countries --maintenance pgp`. The command requires the operator token or root; importing, deleting, and exporting the private key also require an interactive typed confirmation. `generate` creates the project identity and stores its encrypted private key at `security/pgp.priv.asc.enc` and public key at `security/pgp.pub.asc` under the configured directory. `rotate` signs the replacement public key with the old key, publishes it, re-encrypts retained PGP report bodies in one transaction, and keeps the old encrypted private key for 30 days. The detached rotation signature is stored as `security/pgp.rotation.asc.sig`. `publish` submits the public key to configured `web.security.keyservers`; publication attempts are recorded in `security/keyservers.state` and checked by the built-in scheduler for due retries. Use `export public [path]` to print or copy the public key, `export private PATH` for a rate-limited, audited private-key export, `import FILE` to install a private key, or `delete` to remove the pair. Deleting the key makes retained PGP-encrypted reports unreadable. See [CLI maintenance](cli.md#server-maintenance-commands).

## Data and privacy

The service stores no user accounts or profiles. Contact submissions are sent to the configured report recipients and are not added to the country dataset. Security report bodies use OpenPGP when a valid project public key exists and otherwise use AES-256-GCM; researcher contact details always use AES-256-GCM. Status access uses a token delivered by email, valid once per UTC day. Access logs contain the normalized client IP (resolved only through configured trusted proxies), request ID, method, request path, response status, and duration. Apache, Nginx, or a configured custom format may include non-sensitive query parameters; sensitive parameter values such as `token`, `session`, `code`, `key`, `password`, `secret`, `auth`, `pwd`, `api_key`, `apikey`, `access_token`, and `refresh_token` are redacted in every access format and in referer URLs. JSON access logs contain the path without a query string. Operators control deployment logs and retention. Browser theme and language preferences are stored in client-readable cookies; server-rendered state-changing forms use CSRF protection. `/server/dpo` displays only the DPO/general address supplied in configuration and otherwise directs visitors to the deployment's security page; no contact address is invented. Country data provenance and redistribution terms are documented in [`src/data/README.md`](https://github.com/apimgr/countries/blob/main/src/data/README.md).

## Owner tokens and MCP

There are no accounts or passwords. A primary owner token has `global` scope and identifies an anonymous owner while managing linked tokens. Linked tokens have `read` or `read-write` scope (default `read-write`); read scope permits GET, HEAD and OPTIONS, while read-write also permits POST, PUT, PATCH and DELETE on owner resources. Linked tokens cannot manage tokens. The operator bearer token grants global management access and is stored in `secrets.yml`. Owner and linked tokens are encrypted at rest and masked in token lists. Keep token values in the `Authorization: Bearer` header; the `/api/` routes ignore browser cookies. A valid token without the required scope receives `403` and `WWW-Authenticate: Bearer error="insufficient_scope"`. The MCP endpoint requires an owner or linked bearer token and never exposes token-management actions as tools. Give each MCP client its own linked token and revoke it when no longer needed.

## Operator maintenance

The server's `--maintenance` commands require the operator token or root. `token list` exposes token prefixes and metadata, never token values. `token revoke PREFIX` revokes a linked token after a typed-prefix confirmation. Revoking a primary token deletes that owner's tokens and resources after a typed owner-ID confirmation. `--yes` skips that confirmation for scripts.

`data export --owner PREFIX` writes the selected owner's export as a mode `0600` JSON file; `--output -` writes it to standard output. It includes owner and token metadata, never token values. `data delete --owner PREFIX` removes that owner's records and resources after confirmation. `compliance report` shows standards and retention settings, aggregate counts, recent compliance events, last-backup time, and audit-log integrity without personal data.

`security list`, `security show`, and `security update` manage report metadata and researcher-visible comments. They do not reveal report bodies. Updates are audited and send a status notice when email and readable contact data are available.

Rotate the `installation_secret` or at-rest `encryption_key` with `--maintenance secret rotate`. Rotation requires interactive confirmation, re-encrypts dependent data, and keeps the previous value for seven days or 30 days respectively. Startup recovery completes interrupted migrations before services start; the daily security cleanup retires expired previous values. See [CLI maintenance](cli.md#server-maintenance-commands) for command syntax.
